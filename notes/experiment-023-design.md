# 实验 023：完整六表未知密钥搜索加入系统下降

状态：前瞻协议，须完成代码和合成检查、冻结并推送后才生成本轮真实实验密钥。
本轮仍是完整六表未知同音组与未知字母/表归属恢复，不读取手稿。

## 沿用范围与新数据

[实验 022 协议](experiment-022-design.md)中的密钥族、base52 编码、来源选择与规范化、
语言模型、256 行拟合与随后 64 行留出、A/B 划分、公开结构 oracle、语法格、
频率初始化及结构修复、近似最大原子路径评分、状态预算、真值隔离与评价规则，
全部原样沿用，并把该协议作为本轮的规范性依赖冻结。
本协议仅改变搜索中的下降步骤、搜索 seed 和输出命名；相冲突处以下文为准。

重新为两种语言各抽三个私有密钥和独立编码 seed，使用 `secrets.randbits(128)`；
不从 022 所选密钥、真实密钥或其分组初始化。本轮与 022 共享来源作品及明文区间，
不能称全新盲测作品；新隐藏的是密钥和编码 realization。
不改变生成失败时保留失败、禁止按恢复率或编码成败重抽密钥的规则。

## 改进依据

022 的未知密钥恢复全部失败，而真实密钥参考全部通过。
使用其公开训练输入做的[探索性邻域诊断](naibbe-neighborhood-results.md)进一步表明，
每个旧所选密钥都有 818—1015 个简单槽位交换可改善当前路径目标。
这提示先补足下降步骤，尚不保证真实恢复率会提高。

## 固定搜索

保留每条件 12 个 restart、3 轮、每轮 20000 个退火 proposal，
保留 022 的退火温度、移动比例、初始起点及随机数分布实现。
新的公开搜索 seed 是 `202210023+1000*language_index+100*replicate+mode_index`，
restart 的 seed 递增式仍为 022 的固定规则。

每轮退火保留其固定路径最高分的密钥，然后对该密钥执行以下系统下降：

1. 全格解码，固定其完整训练路径。
2. 按下面顺序枚举一次 sweep；每个候选都从**当时最新的密钥**生成。
   若合法且固定路径目标提高超过 `1e-7`，立即接受并更新增量缓存，否则丢弃。
3. 完整 sweep 结束后逐行直接核对分数，再全格解码更新路径。
4. 若本 sweep 没有接受移动则停止；否则重复，最多 32 个 sweep。

一次 sweep 的严格顺序为：角色 U/P/S、角色内槽位 a 从小到大、b 从 a+1 到最后，
共 28359 个槽位交换；然后角色 U/P/S、字母 a/b 从小到大，共 759 个单角色整列交换；
然后 253 个三角色共同整列交换；最后按字母 a、表 t1、表 t2>t1 的顺序，
枚举 345 个 `dar` 两槽整体目标。合计 **29716 个移动 proposal/sweep**。
移动可重复到达同一个密钥，这不是不同密钥数。
不改变多重性、role 内函数性及所有 529 个字母对的正接受概率要求。

下降步骤不使用 RNG，不消费退火随机流。每 1000 个枚举 proposal 及每 sweep 结束，
使用 022 的逐行直接评分核对增量分量，容差保持 `max(1e-7,1e-12×abs(direct score))`。
必须确认每 sweep 恰好 29716 个 proposal、30 次周期/末端核对，
并保存接受数、各移动类别接受数、固定路径/重解码目标、最大误差及耗时。

达到 32 sweep 且最后仍有接受时，记录 `pass_cap_reached=true` 并保留当前合法密钥；
这是已声明的搜索预算终点，不宣称已经收敛，也不增加预算补跑。
零接受仅表示本次列举的固定路径邻域无改善，不是全格目标的全局或完整局部最优证明。

下降结束后的密钥及完整解码目标进入本 restart 的保留与最终选择。
各候选仍只按完整训练目标比较，平分用 slots 字典序；不根据真实恢复率重选。
下一轮从本 restart 已知完整目标最高的密钥继续。

## 阶段、验证与结论

实现为 `src/naibbe_descent_search.cpp` 与原冻结解码器共同编译的 `bin/naibbe_descent`；
调度器为 `src/naibbe_descent.py`。制备写入 `data/naibbe-unknown-v2/`，
结果写入 `results/naibbe-unknown-v2/`，不修改任何 022 文件。
阶段仍为 `freeze → prepare → fit(12 条件) → freeze-fit → predict → score`。
输入冻结绑定新的源码、程序、本文、沿用协议与模块、来源及探索性诊断汇总。
所有密钥选择冻结后才预测留出，全部预测冻结后才对照真值、计算真实密钥参考。

合成检查须覆盖旧增量/直接评分对照、解码穷举、Python/C++ 接口、完整多起点流程，
并检查 sweep 的枚举数、核对次数、目标不下降及停止原因。
新程序不能读取真实密钥或原 CSV 中的字母/表信息。

主要检查仍为 **24 格全部通过**：真路径覆盖 100%、字符编辑准确率至少 99%、
每 32 个 128 字母片段至少 26 个完整恢复。真实密钥参考不能替代未知密钥主结果。
保存全部条件和失败；预算上限、评分近似与既知结构信息都须随结果说明。
若未通过，不能向手稿应用推进；即使通过，也仍需另行识别并校准手稿的结构假设。
