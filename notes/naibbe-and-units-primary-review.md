# Naibbe、槽位结构与分析单位：原始来源阅读

日期：2026-10-02。状态：文献与既有协议评审，尚未形成新实验结论。

本次没有新增手稿计数、拟合或解码，没有检查 f49v 文本，也没有修改冻结输入或结果。下面区分作者实际实现的机制、作者的统计结果和本项目提出的待校准预测。未独立运行这些外部作者的代码。

## 1. 哪一种编码尚未由 010–020 覆盖

最值得保留的是**一个可见密文词承载一个或两个连续明文字母**的扩写编码。它与“一个手稿字形固定输出一个或两个字母”方向不同；也不同于 018 的逐字形输出字母或 SPACE，以及 020 的逐词删除 aeiou。旧实验的失败不能直接转移到这个模型类。

Greshko 的 Naibbe 提供了具体构造：删去原文空格，把规范化字母流重新分为一、二字母块；单字母块查单项表，双字母块查前缀与后缀表后拼接，表的选择由牌组控制。一个密文词因此不是原文词。六张表与三种位置角色产生同音选择。这里保留的是规范化字母流，原始空格、大小写和标点不能由此自动精确复原。[Greshko 2025，§2，原文](https://www.tandfonline.com/doi/full/10.1080/01611194.2025.2566408)、[作者代码](https://github.com/greshko/naibbe-cipher)、[作者归档数据](https://doi.org/10.5281/zenodo.16415087)。

原文 §2.7 明确承认单项/双项及不同双项读法的碰撞，建议在编码时重抽牌消歧；仍可能留下的读法需用上下文选择。作者解码器也会返回多个双字母候选。因此不能把摘要中的 fully decipherable 当作“任意设置下数学上唯一可逆”的证明。新正对照必须冻结确切版本、消歧规则与空格删除规则，逐字符验证完整规范化字母流往返，并另记未能唯一恢复的比例。[原文 §2.7](https://www.tandfonline.com/doi/full/10.1080/01611194.2025.2566408)、[作者解码器](https://github.com/greshko/naibbe-cipher/blob/main/decrypt_naibbe.py)。

表项和权重本来就为伏尼契式词形及频率设计；复现这些相似性是构造的能力展示，不能再充当独立的语言证据。作者仓库现有额外变体；以后若引用“2025 Naibbe”，须固定论文归档或明确版本，不把后加规则合并进原始模型。

## 2. 两篇 2022 年研究实际支持什么

**Bowern 与 Gaskell。**《Enciphered after all?》实际比较了 22 种文本变换及词级统计，包括字母扩写成双符号串，也包括删元音、合并符号、字母排序等有损变换。因此“某些密文与手稿统计距离较近”并不统一意味着可逆，更不意味着已恢复连续文本。它支持将扩写编码列入正对照，不能指定一套手稿密钥。不要与同年作者顺序相反的《Gibberish after all?》混为一篇。[原文，尤其变换表和讨论](https://ceur-ws.org/Vol-3313/paper6.pdf)、[另一篇原文](https://ceur-ws.org/Vol-3313/paper4.pdf)。

**Zattera。**其 12 槽模型是对字形串的形式结构描述，不是明文语法：在经一致性筛选并排除不明符号的样本中，86.6% token 满足槽序，另有 10.4% 可拆成两个合规部分。这个分母不是完整未过滤手稿。槽结构可用来限制合法码字形状，却没有给出槽位到明文字母的对应或唯一可逆码本；规则是根据所分析词形构建的，不能把覆盖率当作独立留出预测率。也不能由槽结构直接宣布所有自然语言都不可能。[论文 §§2.1–2.3](https://ceur-ws.org/Vol-3313/paper10.pdf)、[作者原始方法说明](https://mzattera.github.io/v4j/005/)。

这里有一个具体结合点：Naibbe 的码字结构受到此类槽语法启发，而不是从手稿破译后得出的。将同一槽结构既用于设计生成器，又用于证明生成器像手稿，会重复使用证据。

## 3. arXiv:2608.17096 的来源与解释边界

[Rozanova 与 Temerev，v1，2026-08-17，全文](https://arxiv.org/html/2608.17096v1)及[作者复现仓库](https://github.com/lrozanova/voynich-units)确实存在。其主数据是 ZL3b，另用 v101；使用书帖重采样、BPE 与另一套替换攻击。本项目 019 使用冻结 GC 槽位和训练/留出页，方法与文件接口不同。未在所读论文或 README 中找到本项目仓库或报告引用；本地最早归档提交日期为 2026-10-02，晚于该预印本。现有证据不支持把它判为本项目结果的重发，但没有做穷尽的代码谱系核查。

共享手稿、公共语言文本以及相似的校准思路，不等于独立新数据。该文的图、附录、GitHub 结果和直接像素复核属于同一研究，不能累计为多个外部重复验证。其坐标来源构造文档也不完整，作者在 §4.2 主动说明这一点。

该文报告：跨词末—首字形关联明显，而整词的偏差校正互信息较小；Naibbe 与复制生成器复现了若干统计外观，却没有复现所测边缘关联。它还明确指出 Naibbe 超出其替换攻击已校准的范围，不能用该攻击失败排除这种密码。上述内容可提供新待检验约束，不能识别语言。[原文 §§2.10、3.2、3.9、4.1、5.2、附录 A.5](https://arxiv.org/html/2608.17096v1)。

### 信息论上必须收紧的一句话

对未截断的整词随机变量 W，末字形 L(W) 和首字形 F(W) 是确定函数，故必有：

`I(L(W_t); F(W_{t+1})) <= I(W_t; W_{t+1})`。

所以不能将“边缘信息大于整词信息”理解为总体信息真的只存在于边缘、整词身份对它不可见。该文整词类别有词表上限及 UNK 粗化，并对插件估计减去置换均值；边缘表示保留的区别可能已经被整词 UNK 合并。不同维度的有限样本偏差也不同。这些估计之间没有上述总体不等式保证。作者承认整词原插件值的 98% 来自置换基线，但仍用了较强的“order lives at the edges”措辞。

这里的数学限制不否认跨边界关联存在；它要求把结论写成“在该样本与估计方案中，边缘表示较容易测到关联”。若要声称末字形足以解释可预测结构，应在同一目标变量上比较嵌套模型，并对额外信息做有检验能力的等效性分析。

这也不是 019 的外部复现。019 的边缘指标是前词**末两个原子**预测后词**首两个原子**，检验冻结训练模型在留出页的对数预测增益；该预印本的主要对照是一个末字形与一个首字形的同样本互信息及置换扣除。表示粒度、样本、稀疏度、拟合与评价划分都不同。019 的相应语言正对照未通过，因此当时的负增益不能排除语言；新论文也不能替它补上校准。[019 冻结设计](experiment-019-design.md)、[019 报告](report-015-zh.md)。

## 4. 一项建议登记的新预测

建议只先检验：**前词末字形是否可充当跨词可迁移的有限边界状态**。这比继续增加字母映射自由度多了一项可失败的机制约束，也直接对应一种尚未测试的编码：同一明文字母块的同音码选择受到前一密文末字形控制。

统一把“下一 token 的首个完整字形”作为预测目标，冻结三个嵌套模型：M0 使用位置和边际分布；M1 在 M0 上加入前 token 末字形；M2 在 M1 上加入前 token 其余身份信息。主预测是 M1 有可迁移的正增益，同时 M2 的剩余增益小于预先规定的实质阈值。后一个条件必须用正对照证明能检测到该阈值大小的差异；不能以不显著或复杂模型表现更差代替“没有剩余信息”。不再比较两个不同目标字母表的互信息比值。

必要校准是一组配对的已知可逆扩写密文：固定一、二字母块及一码多形规则，一版使用预定的无边界状态选择，另一版只加入已知的边界状态依赖；两者都要精确往返恢复完整规范化字母流。独立打乱明文字母块后重复这一对照，可验证检测到的状态依赖本身并不意味着有自然语言。公开 Naibbe 的固定版本可作额外困难正对照，但不能代替这个机制已知的配对对照。

先仅用合成对照选定表示、预算、检测能力及等效性阈值，再冻结后使用已有允许的手稿分割；未知槽、物理行及来源断点必须按同一规则处理。完整字形须保持原子性；若加 EVA 敏感性，需预定组合处理，避免把转写拆分造成的确定关系误认作编码状态。不能根据手稿结果再选择有利的 y→q 等字形对。

若校准失败，停止解释手稿上的空结果。若手稿不满足该预测，只是否定这个具体的可迁移边界状态近似。若满足，也只是约束下一步码本设计：**没有识别一个 token 的一、二字母载荷，没有得到读音或译文，也没有排除其他语言、扩写编码或伪文本生成。** 在未知密钥恢复正对照达到完整连续文本的预定标准之前，不应开始凭局部好看词评价 native 解码。
