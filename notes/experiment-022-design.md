# 实验 022：完整六表、未知同音组与未知字母映射

状态：待冻结的前瞻协议。只有代码、合成检查和本文均被输入冻结绑定并推送后，
才生成本轮实际私有密钥及实验密文。本实验不读取或解码伏尼契手稿。

## 问题与边界

实验 021 给了真实码表。本轮隐藏同一个字母的码串分组、三个角色之间的字母对应，
以及各码串所属的表，同时保留完整六表条件；不以共享 23 字母改名或两个同音项玩具代替。
恢复对象仍是规范化的无空格连续字母流，不包括原文词界、标点及被规范化的拼写区别。

明确提供的额外信息是：23 字母表、匹配语言先验、U/P/S 角色及其表面库存、
角色内码串多重性、完整六张表、52 张牌的权重、`U | P S` 语法、重分块及删边界概率。
这些是合成校准的 oracle，不是已经从手稿识别出的事实。不给真分组、字母标签、
原 CSV 行序、真实表归属、真实分块、牌堆状态、明文长度筛选或随机种子。

即使本轮全部通过，也只能说明给定这些结构信息时的未知密钥恢复通过了校准；
不能据此宣布手稿使用 Naibbe 机制、识别其语言或开始直接宣称译读。
失败也不能排除语言或密码家族。手稿结构识别与应用须另立协议。

## 密钥族与编码

原始机制使用已经归档的作者仓库 `f2675ec5` 中 `naibbe.py` 的 base52 版本，
不使用 strict-v2、78 张牌或重复片段变体。作者来源、许可及机制差异见
[通道核对](naibbe-channel-review.md)。编码复用冻结的 `src/naibbe_channel.py`。

三个角色各有六张 23 字母表，权重顺序是 `20,8,8,8,4,4`。
U 有 137 个不同表面码串，其中 `dar` 占两个槽位，并须对应同一未知字母；
P 和 S 各有 138 个不同码串。随机分配整个槽位，保留多重性但不保留码串原有权重。
对 U，均匀选一个字母及两个不同表，放入 `dar`，打乱其余 136 个码串填充剩余槽位；
P/S 分别打乱 138 个码串。槽位按表、字母排序，码串输入按字典序。

如果某个字母对的全部 36 个 P/S 表组合都拼成 U 码串，则整个密钥提案被拒绝。
逐一检查 529 个字母对，记录拒绝提案哈希及无支持字母对；最多 10000 份提案。
这只是源文本和恢复分数之外的结构条件。预算耗尽立即失败，不返回部分密钥。
实际文本编码达到每行 1000000 次抽牌预算时也失败；不得因此重抽密钥或重选源文本。

每语言三个独立私有密钥。密钥与编码分别使用 `secrets.randbits(128)` 生成 seed，
仅保存在与求解器输入分开的真值文件中，失败时也保留。不存在公开可重构的真实密钥 seed 公式。
这里“私有”指求解器不可读取；合成实验的真值仍归档以供预测冻结后的独立复核。

base52 每行先按单字母概率 `17/36`、双字母概率 `19/36` 重分块，
最后剩一个字母时强制单项；然后从真实有限牌堆依次抽表，耗尽后重建并洗牌。
P/S 拼接若等于任意 U 码串则拒绝重抽，消费已经抽出的牌；不排除其他双字母歧义。
每行重新开始牌堆，同一 case 的 RNG 跨行延续。编码后用同一个 RNG，
按原码词内部边界顺序以 `.03` 概率删除边界，再开始下一行。
保存删除前 preserved 与删除后 deleted 的配对观察，不分别重编码。

## 来源、划分与语言模型

沿用实验 021 的原始正文选择和作者规范化：Latin 保留 u/v，`J→I,K→C,W→UU`。
语言模型使用 Caesar《高卢战记》书 1–7 或已冻结的 Dante 记录全文；
密文来源分别为 Cicero《反喀提林》演说 1–4 或已冻结的 Boccaccio 记录。
原始文件、提取模块及选择记录均进入冻结，不重新选择作品。

每部密文来源前 `256×128=32768` 个字母是密钥拟合段，
随后 `64×128=8192` 个字母是留出段；后者前后各 32 行为 A/B。
每行 128 个字母，只用于制备和评价，求解器不得按真实长度筛选。
先连续编码拟合段，再编码留出段。作品不足长时失败，不循环使用或借用其他来源。
这些作品此前已被使用，不能称全新盲测作品；本轮隐藏的是新密钥。
同语言不同密钥、同密钥两种边界条件共享明文，不能视为独立语言样本。

语言模型与 021 同式：128 字母切块，保留最后短块，BOS/BOS 开始并预测一次 EOS；
P0 的 24 个预测符号使用 additive `.5`，P1/P2 用 `tau=20` 层次回退。
使用完整的字符 trigram 联合概率，不按候选长度平均；跨可见密文空格保持 history。
C++ 二进制模型保存 `24³` 个小端 binary64 log 概率；23 在 history 中表示 BOS，
在预测结果中表示 EOS。不可达的 history 行填入 P0，实际路径不能产生 EOS 后续 history。

## 公开语法格与初始密钥

码串 ID 按角色 U/P/S、角色内字典序排列，不保留作者字母、表名或行序。
格边是一个 U 原子或一个 P/S 原子对，P/S 拼接为 U 时排除。
preserved 每个观察 token 恰好是一条码词边；deleted 允许任意多个码词边拼接，
不限制连续删除次数。任何边都不得跨过仍可见的 token 边界。
格边按 `(from,to,first,second,token)` 排序，cipher position 为去空格的字符边界。

初始计数只用语法：选完整路径中边数最少者，同边数时取 edge-id 序列字典序最小者。
这不是断言它是真实分块。按原子计数和 `P0(letter)×mass/52` 的排序配对填满合法槽位。
U 的重复项穷举 `23×15` 个字母和表对，剩余码串按上述排序填充，
选 `sum(count×log(rate))` 最大者；相同分数以完整 slots 字典序破平。
使用 log rate 排序避免下溢，P0 去掉 EOS 后重新归一化。

如果初始 rank key 有零接受概率的字母对，则使用固定的纯结构修复：
`Random(2200022)` 连续消费，每次从 rank key 新副本开始，做 414 次保留角色和多重性的随机交换。
P/S 普通槽交换；U 非重复项与非重复项交换；选中 `dar` 时将两份整体迁至随机字母和随机两张表，
被挤出的项按槽位顺序移回旧位置。最多 10000 次尝试，取首个全字母对有支持者，
不按任何恢复或训练目标分数选择。保留计数、最初路径、proxy、修复次数及 RNG 状态哈希。

## 评分和搜索预算

候选密钥始终属于完整六表槽位置换族。某码串的 emission 质量是它在该字母槽位的牌权重之和除以 52。
令 `B_ab` 为映射至字母 a/b 且其 P/S 拼接属于 U 的全部原子对的权重乘积之和，
则每个 PS 项使用接受概率 `Z_ab=(2704-B_ab)/2704` 的倒数归一化。任何 `B_ab≥2704` 的密钥非法。

完整路径目标是连续 trigram+EOS，加各原子 log emission，减每个 PS 的 `log Z_ab`，
再加重分块及边界项：非末 U 使用 `log(17/36)`、末 U 使用 0、PS 使用 `log(19/36)`；
deleted 中隐藏边界使用 `log(.03)`、仍可见的内部边界使用 `log(.97)`，行末不加；
preserved 不加删除概率。

这是**有放回近似下的最大原子路径分数**，不是有限牌堆的精确 likelihood、后验或边缘字符串 MAP。
与 021 先合并相同可见串/明文字母块的语义 emission 略有区别：本轮不将不同 P/S 原子分解边缘化。
因此预测冻结后还要给真实密钥运行同一个新解码器作为参考，检验这项近似自身的恢复能力。

共 12 个独立拟合条件：2 语言×3 私有密钥×2 边界模式。配对条件不能互读。
每条件固定 **12 个 restart、每个 3 轮、每轮 20000 个 proposal**，共 720000 proposal。
公开搜索 seed 是 `202210022+1000*language_index+100*replicate+mode_index`。
各 restart 使用 `mt19937_64(seed+0x9e3779b97f4a7c15*restart mod 2^64)`，
整数采用显式拒绝采样，uniform 用最高 53 位，shuffle 用 Fisher–Yates。

restart 0 用 rank/修复后的初始密钥；奇数 restart 从同一初始密钥做 64 个合法且不同的随机 move，
最多 6400 次尝试；其余偶数 restart 从角色槽位随机排列开始，随机选择重复项的字母和两张表，
仅按结构合法性拒绝，最多 10000 次。都先完成一次全格解码。

每轮固定当前最优密钥的完整解码路径，退火搜索合法槽位；保留这轮固定路径目标最高的密钥，
再运行完整未剪枝 Viterbi 更新路径。下一轮从该 restart 的完整目标最优密钥继续。
move 比例：70% 同角色普通槽交换、15% 单角色整列字母交换、10% 三角色共同字母列交换、
5% `dar` 两槽整体迁移；非法 proposal 消费预算但不接受。
温度为 `(fixed_parse_atoms+rows)×.02×(.00005/.02)^(step/(steps-1))`；单步时 progress=1。
非负 delta 接受，否则按 `log(U)<delta/T`，仅负 delta 消费 acceptance RNG。
这不是声称从密钥后验采样。

增量缓存原子 trigram、原子计数、PS 对和字母对计数。Z 改变时须计入该字母对的全部实例，
包括未直接涉及被移动码串的实例。每 1000 次 proposal 及末次，与逐行直接重算核对，
阈值 `max(1e-7,1e-12×abs(direct score))`，各分量也核对；不符即失败。

所有 restart/轮及初始候选均记录。只按**完整训练解码目标**选最终密钥，
相同浮点分数以 slots 字典序破平；不查看真值、留出观察或恢复率来选。
Viterbi 状态为 cipher position 与末两个字母，每行最多 1000000 个实际到达状态，
包含 BOS 起点，EOS 不另计状态；超过预算明确失败，不静默剪枝。
遍历位置、history、输入 edge 顺序，严格更高分时更新，末端亦按 history 顺序严格更新。

## 阶段隔离与评价

阶段依次是 `freeze → prepare → fit(每条件) → freeze-fit → predict → score`。
所有输出排他创建，失败保留记录，不覆盖旧运行。输入冻结绑定源码、可执行文件、协议、来源和配置；
制备冻结绑定所有公开观察、模型、初始密钥和分开的私有真值。
全部 12 个密钥选择冻结后才解码留出段；全部预测冻结后才读取真值、真实密钥或真实路径进行评分。
拟合/预测阶段允许完整性哈希读取私有文件字节，但不能解析其内容。
C++ 求解器只接收公开库存、一个条件的格、模型和候选槽位文件，无真值接口。

24 个主要评价格为未知密钥的每语言×密钥×模式×A/B。每格必须同时满足：

- 真路径在公开语法格、真实密钥诱导映射下的覆盖率 100%；
- `1−总字符Levenshtein距离/总真实字符数 ≥ .99`；
- 完整 128 字母行精确恢复率 ≥ .80，即每 32 行至少 26 行完全正确。

全部 24 格通过才记本次未知密钥校准通过，不取平均掩盖失败，也不只报告最好的 seed 或模式。
同一新解码器给定真实密钥的 24 格为诊断参考，不得替换未知密钥主结果。
同时保存各行错误、状态数、路径评分复算、全部 413 原子的字母/质量恢复及拟合段未出现原子。
等权 beta/gamma 表名存在不可识别置换，因此不以恢复任意内部表名为标准。

失败诊断区分：真路径缺失（制备/语法问题）；真实密钥仍恢复失败（评分/解码近似问题）；
真实密钥训练目标较高（搜索未达该已知可行目标）；错误解目标更高（目标与真实恢复不一致）。
真实密钥的训练目标及留出参考只在未知密钥预测冻结后计算，不能反馈搜索。

本轮不进行伪文本识别或语义分类，不设打乱文本主比较，也不根据“读起来像语言”评价破解。
恢复门槛失败、任何必要阶段预算耗尽或校验失败时，保留证据并停止向手稿应用推进。
